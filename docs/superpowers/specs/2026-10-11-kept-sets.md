# Kept Sets — "keep a set, I'll tell you when it moves"

**Date:** 2026-10-11
**Status:** Design — awaiting review

## Goal

Make weft's most distinctive-but-illegible claim (certification) *felt*, by
reframing it as the thing people actually want: **keep a set you care about, and
weft tells you — in plain terms, ignoring noise like renames — when and how it
moved.** The digest/manifest becomes invisible plumbing; the human-facing concept
is a *kept set* with a calm freshness state.

Why this reframe: certification's value is entirely about *change*, and it was
only ever shown at the moment of sealing — when nothing has changed yet — as an
opaque hash. We surfaced the artifact before the user had the problem it solves.
Kept sets surface the *state* ("holds" / "moved") and speak up only when a set
actually moves, in the user's own rows.

Supersedes the user-facing framing of `pull --verify` / "certify this slice" /
the Loom's "lock this slice" — not the plumbing beneath them (`manifest.py`
stays; `drift.py` stays as the ALab finish specialist).

## The principle that makes it good

1. **Calm by default, specific when it speaks.** A set that holds shows a quiet
   green dot and nothing else. A set that moved shows a count and, on click, the
   specifics. Never an opaque hash in your face.
2. **The diff lives in the table you already explored in.** No new "drift report"
   screen — the same Loom pivot that *assembled* the set shows it *move*, as
   annotations on the rows (`+ arrived`, `! changed`, `− gone`, `renamed ·
   ignored`).
3. **Renames stay quiet.** A kept set tracks *identity*, not bytes, so a rename
   is shown greyed and labeled *ignored* — the trust signal that it only cries
   wolf when the set truly moved.
4. **One vocabulary everywhere** — *keep · kept set · holds · moved · arrived ·
   changed · gone · renamed* — across the Loom box, the CLI, and the viewer. No
   "certify / manifest / digest / receipt" in any user-facing surface.

## Vocabulary (the one language)

| Concept | Word | Not |
|---|---|---|
| save a set to watch | **keep** | certify, lock, seal, pin |
| the saved thing | **kept set** | receipt, manifest, snapshot |
| nothing moved | **holds** (● green) | valid, verified, clean |
| something moved | **moved** (⚠ amber) | drift, invalid, stale |
| a new member | **arrived** | — |
| a member whose read changed | **changed** | — |
| a member that's gone | **gone** (departed internally) | — |
| same thing, new name | **renamed · ignored** | — |
| re-run the check | **re-check** | verify |
| re-save at the new state | **accept** | re-seal, re-certify |

## Engine — `weft/kept.py` (new, general)

A general "watch any box expression" layer, distinct from `drift.py` (which stays
the ALab finish-facet/tier-identity specialist). `kept.py` reuses existing weft:
`compose.parse_expression` + `pull.pull` to resolve the set, `ask.identity_of`
for identity, and `UsdShade.MaterialBindingAPI.ComputeBoundMaterial` for the read.

**Member read** — the few things whose change *is* the drift that matters:
```python
read(prim) -> {"type": <typeName>, "material": <bound full material path or None>}
```
(Kept deliberately small; extensible later. A member also carries its `id` =
`ask.identity_of(prim)` or `None`, and its `path`.)

**`capture(stage, expression) -> dict`** — the kept-set record:
```json
{ "name": "...", "expression": "where:material=...glass",
  "created": "2026-10-11T...", "usdVersion": "...",
  "members": [ {"path": "...", "id": "...|null", "read": {"type":"Mesh","material":"..."}} ] }
```
Resolve via `pull.pull(context, e.seeds, follow=e.follow, depth=e.depth)`; record
every member's path, id, and read.

**`check(record, stage) -> dict`** — re-resolve the expression against the current
stage and diff recorded ↔ current:
```json
{ "holds": false,
  "arrived":  [ {"path":"...","read":{...}} ],
  "changed":  [ {"path":"...","old":{...},"new":{...}} ],
  "gone":     [ {"path":"..."} ],
  "renamed":  [ {"old_path":"...","new_path":"..."} ],
  "counts": {"arrived":1,"changed":1,"gone":1,"renamed":1} }
```
Matching rule:
- Pair recorded ↔ current **by `id`** when both have one; otherwise **by `path`**.
- Paired, same read → unchanged (silent). Paired by id but different path, same
  read → **renamed** (inert). Paired, different read → **changed**.
- Recorded, unpaired → **gone**. Current, unpaired → **arrived**.
- `holds` = no arrived, changed, or gone (renames don't break hold).

Never raises on a bad expression or a vanished member — degrades to honest
entries. The digest (`manifest.digest` over the record) is computed and stored
but never surfaced; it's the tamper-check plumbing.

## Storage

Kept sets are sidecar JSON under the enclosing project: **`.weft/kept/<name>.weft`**
(mirrors `drift`'s `.weft/receipts/`). `name` is slugified. Helpers:
`save(record, dir)`, `load(name, dir)`, `list_kept(dir) -> [names]`,
`kept_dir()` (find/create `.weft/kept/` at the project root, same resolution as
`_receipts_dir`).

## Loom — server

`LoomState` gains, all thin wrappers over `kept.py` + the already-open stage:
- `keep(name, expression) -> record` (capture + save)
- `kept() -> [ {name, expression, state: "holds"|"moved", counts} ]` (load all,
  `check` each against the current stage — this is the glanceable strip's data)
- `check_one(name) -> {record meta, ...check() diff...}` (the "what moved" detail)
- `forget(name)` (delete a kept set)

Endpoints: `POST /keep {name, expression}`, `GET /kept`, `GET /check?name=`,
`POST /forget {name}`. All return `{error}` on failure, never 500.

## Loom — UI (`app.html`)

1. **Keep, in the slice bar.** Replace the slice bar's `lock this slice` with
   **`keep this set`** → prompts for a name (default: the expression, slugified),
   POSTs `/keep`, adds it to the strip. (`view as graph` / `export` stay.)
2. **The kept strip** — a slim row under the header (hidden when there are none):
   ```
   KEPT:  ● glass-set      ⚠ bench-props · 3      ● hero-shot
   ```
   Each chip: a dot (green holds / amber moved), the name, and the move count when
   moved. Loaded from `/kept` on page load and after any keep. Click a chip →
   loads that set's expression into the box (so the table shows it) and, if it
   moved, shows the diff (below).
3. **"What moved" = the pivot, annotated.** When a moved set is opened, the table
   rows carry diff marks: `+ arrived` (green), `! changed glass→matte` (amber),
   `− gone` (greyed ghost row), and `renamed from X · ignored` (greyed, small).
   A thin header above the table: `glass-set · moved · 3 changes [ re-check ]
   [ accept ]`. `accept` re-captures at the current state (POST /keep same name);
   `re-check` re-fetches `/check`.
4. **Calm.** A set that holds adds no marks and no header — clicking it just loads
   its slice normally. The strip is the only persistent surface; it's silent when
   everything holds.

No "certify / digest / lock" strings remain in the UI.

## CLI

Reworded over `kept.py`, one vocabulary:
- `weft keep "<expression>" --as <name> [<stage>]` → capture + save; prints
  `kept '<name>' — <N> things`.
- `weft check [<name>] [<stage>]` → `check` one (or all kept sets); prints the
  plain report (`holds`, or `moved · +1 arrived · 1 changed · 1 gone · 1 renamed
  (ignored)` with the per-member lines). Exits non-zero on moved (CI gate),
  renames alone stay zero.
- `weft forget <name>` → delete.

The existing `weft pull --verify` and `weft drift …` stay (plumbing / ALab
specialist) but are no longer the headline; `--help` leads with keep/check.

## Viewer (secondary, this spec)

When a kept set's slice graph is shown and it has moved, tint **arrived** nodes
green and ghost **gone** nodes. Nice-to-have; the table diff is the primary
surface. May land in a follow-up.

## Data flow

1. Keep: box has an expression → `keep this set` → `POST /keep` → `kept.capture`
   (pull + read each member) → `save` to `.weft/kept/`.
2. Page load / after keep: `GET /kept` → `check` every kept set against the open
   stage → strip shows dots + counts.
3. Click a moved set: `GET /check?name=` → the diff → annotate the pivot rows.
4. Accept: `POST /keep` (same name) → re-capture at current state → dot goes green.

## Error handling

- Bad expression on keep → `{error}` shown by the box, nothing saved.
- A kept set whose expression no longer parses (grammar changed) → shown in the
  strip as `? unknown` with the error on hover, never a crash.
- `.weft/kept/` unwritable → keep reports it; the rest of the Loom is unaffected.
- A member with no `id` → matched by path; a rename of such a member honestly
  shows as gone + arrived (no false "ignored"), because without identity we can't
  prove it's the same thing. (Stated, not hidden.)

## Testing

- `test_kept_capture_check` — capture a set; no-op check holds; add a member →
  arrived; remove one → gone; rebind a member's material → changed.
- `test_kept_rename_is_ignored` — a member with an `id` whose path changes, same
  read → renamed, `holds` stays true.
- `test_kept_no_identity_rename_is_honest` — same, but member has no id → gone +
  arrived, `holds` false (we don't fake it).
- `test_kept_storage_roundtrip` — save/load/list under `.weft/kept/`.
- `test_loom_keep_endpoints` — `/keep` then `/kept` shows it; `/check` returns the
  diff; `/forget` removes it.
- Loom serving markers: `keep this set`, `id="keptstrip"`.
- Full suite stays green.

## Out of scope / YAGNI

- Generalizing or replacing `drift.py` (the ALab finish specialist stays as-is).
- Watching across *multiple* stages / a shared asset resolver (single open stage
  only, as the Loom is).
- Scheduled/background re-checks (checks run on open and on demand — the quiet
  guarantee, not a daemon).
- Per-member diff of arbitrary attributes (the read is type + bound material in
  v1; extensible).
