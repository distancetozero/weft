## Lane A — Grammar (`weft/ask.py`, `tests/test_ask_resolve.py`)

Mirror the existing `material:` seed (added in the same file: `parse_seed` entry
+ a `resolve_seeds` branch + tests with their own tmp fixtures).

### A1 — `type:<value>` selector (firm)
Prims whose `GetTypeName()` matches `<value>`: fnmatch on the type name
(`type:Mesh`, `type:*Light`). Closes the Loom's "organize by Type — no slice
expression yet" caption.
- `parse_seed`: `if t.startswith("type:"): return Seed("type", "", t[len("type:"):], t)` (add before the `material:`/`path:`/`name:` block).
- `resolve_seeds`: `elif s.plane == "type":` → `r.mode = "type"; r.paths = sorted(p.GetPath().pathString for p in prims_list() if fnmatch.fnmatchcase(str(p.GetTypeName()), s.value))`; a no-match sets `r.note`.
- Tests: `type:Mesh` → the meshes; `type:*Light` glob; no-match notes. (Build a tiny tmp stage with a Mesh, an Xform, a SphereLight.)

### A2 — reverse selector (deliver if clean; else deliver A1 and flag A2 for 0.1.2)
"What points *at* this." First READ `weft/cli.py`'s `cmd_who` and whatever
reverse-edge function it calls (and `weft/threadgraph.py`) — reuse that machinery
rather than reinventing. The cleanest surface is a seed:
- `who:<inner-seed>` → prims that depend on (point at) the prims matching the
  inner seed, e.g. `who:name:glass` = what points at the glass prims.
- Parse: `who:` prefix carrying the rest as an inner seed; resolve by running the
  existing reverse/incoming-edge lookup against the inner seed's paths.
- If the existing reverse machinery doesn't factor out cleanly into a seed within
  a reasonable effort, STOP, deliver A1 solidly, and report A2 as deferred with
  what you found — do not ship a half-working reverse.
- Tests (only if built): a prim with `rel foo:bar = </root/x>`; `who:path:/root/x`
  includes that prim.

Commit A1 and (if built) A2 separately with clear messages + trailers. Full suite green at the end.

- **Ship the plugin files.** The plugin lives at `extras/usdview/weftViewer/`
  (`__init__.py`, `core.py`, `threadpanel.py`, `webenginepanel.py`,
  `_stagebridge.py`, plus any `.html`/`plugInfo.json`). First READ
  `extras/usdview/` to see the full file set and where `plugInfo.json` lives.

  keeps the plugin importable as `weftViewer` AND ships `plugInfo.json`:
  1. Add `weftViewer` as a package via `[tool.setuptools.package-dir]`
     (`weftViewer = "extras/usdview/weftViewer"`) in `packages` + `package-data`
     for its non-`.py` files; or
  2. Ship the whole `extras/usdview` tree as data under the `weft` package and
     have the helper (below) point `PXR_PLUGINPATH_NAME`/`PYTHONPATH` at it.

  (`zipfile` namelist), and that `twine check` still passes.

  correct whether weft is installed (site-packages) or editable.

  path changes, update that section to show `export PXR_PLUGINPATH_NAME=$(weft usdview-plugin-path):$PXR_PLUGINPATH_NAME` etc.
