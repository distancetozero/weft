weft

Pull the thread, not the world.

weft answers the questions your USD can't: Who depends on this? What breaks if I republish it? Give me just the translucent things — and tell me what I'm missing.

You stand at any point — a name, an identity, an attribute — and pull only the threads you care about. A thread is any relationship: a material binding, a mount contract, electrical:feeds, or a kind your team defines. Hierarchy is just one thread on the spool. The same premise runs wherever scenes outgrow their files — film, games, manufacturing, AEC, robotics.

Addresses, not paths

weft pull id:hero-car                    # identity — survives restructures
weft pull id:occ:weld-47                 # one placement, restructure-proof
weft pull role:propSocket                # by contract role
weft pull 'where:finish=translucent'     # by attribute
weft pull 'near:id:rack-R42,5'           # within 5 units of a thing, by name
weft pull b01 --follow up:electrical:feeds*8   # trace upstream, 8 hops
weft pull path:/root/shelf01/b_0004      # location — the fallback, not the default
weft who 'name:glass' --context shot.usda      # what depends on this prim?

Where the attributes come from

Nothing above is hand-annotated. Every attribute weft reads has one of four provenances, and the provenance is recorded with the value:

  • Derived from data already there. finish comes from authored UsdPreviewSurface opacity; mount frames from the assembly's own translates; provides sets from the department sublayers. The extractor derived all 601 contract surfaces on ALab from the files as shipped.
  • Derived by a stated rule, recorded beside the result. A consumer's tolerance is 10% of its own authored extent — and that rule is stamped on the interface next to the number, so derivation is never mistaken for measurement.
  • Policy, marked as policy. The provider's default envelope carries source = "policy:extractor-default" — visibly an assumption, never disguised as a promise.
  • Declared by you. Team relationship kinds, edge extractors for your soft-reference conventions, identity keys — your existing GUIDs or part numbers become id: addresses.

And unauthored data yields no attribute, ever: only 8 of ALab's 158 look files author opacity, so 150 props got no finish — an invented "opaque" would be a claim nobody made. Receipts count the complement ("matched 212; 340 don't author this — not evaluated"), so sparse data degrades to declared ignorance, not confident nonsense. With no extraction at all, name:, path:, and the stock USD kinds still work bare on any file — the richer planes bootstrap from your data; they're not a precondition.

Three rules keep pulls trustworthy

  • What you didn't pull is declared, never silently absent. Every boundary is counted by kind, and omissions carry a class: inert (a grey material) or meaning-changing (a physics joint that would silently re-anchor to the world).
  • Every answer carries a receipt. Seeds, follow rules, cost, layer hashes, a digest — a pull is verifiable by recompute-and-compare, on any machine.
  • Compatibility is measured, not asserted. A republish is checked against every consumer's own declared tolerance, not just the provider's promise — and a refusal names each broken consumer with what it tolerates.

What a refusal looks like

A shelf is raised 0.7 cm — inside the provider's own 1 cm promise, so the provider's self-check passes. The consumers are measured anyway:

   consumer re-evaluation (what was measured): 164 consumers checked, 19 broken

The channel never moved. Both refused revisions still exist in the ledger and can be inspected. The tolerances weren't invented — each is derived from the prop's own authored extent by a stated, recorded rule.

Still USD, all the way down

Everything composes and renders through unmodified stock USD — the images above came from the usdrecord binary that ships with macOS. Masks, payloads, LoadNone: USD's own machinery, fed by weft's answers. Every persistent artifact is real USDA; contracts are codeless applied schemas; nothing is ever re-rooted or rewritten. Deferral, never extraction.

For teams that want ground truth and not just queries, the engine adds a content-addressed store, immutable revisions, channels, and the measured promotion gate — offline, serverless, git init-shaped. Runs on any USD file with no server and no schema changes.

Try it

git clone https://github.com/distancetozero/weft
cd weft && pip install -e '.[usd]'      # PyPI package (weft-usd) coming
weft pull 'where:finish=translucent' --context your_scene.usda --mask-out pull.mask
usdrecord --mask "$(tr '\n' ',' < pull.mask)" your_scene.usda out.png
